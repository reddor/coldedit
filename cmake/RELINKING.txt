TOOLCHAIN.txt records the compiler and platform used for this particular kit.
Use a matching toolchain when relinking precompiled application objects.

Windows: use the matching MSVC x64 compiler and Windows SDK,
CMake >= 3.24, and Ninja, from an x64 developer shell. In this directory:
  cmake -S . -B out -G Ninja -DCMAKE_BUILD_TYPE=Release
  cmake --build out
The result is out/coldedit.exe. Close ColdEdit before replacing its executable.

Linux: use the matching GCC/G++ toolchain, CMake >= 3.24, Ninja and OpenGL
development libraries (libgl1-mesa-dev on Ubuntu). In this directory:
  cmake -S . -B out -G Ninja -DCMAKE_BUILD_TYPE=Release
  cmake --build out
The result is out/coldedit. Keep the original package's licenses and relink kit.

Web: activate Emscripten 4.0.23 and install CMake/Ninja. In this directory:
  emcmake cmake -S . -B out -G Ninja -DCMAKE_BUILD_TYPE=Release
  cmake --build out
Copy out/coldedit.js, out/coldedit.wasm, and out/coldedit.data into a copy of the
original web package. Serve it with the included serve.mjs and isolation headers.
The compiler obtains its standard GLFW 3.4 contrib port as in the original build.

Edit lame/ before building to use a modified library. The existing application
objects use the public LAME 3.100 C ABI; preserve that ABI when replacing LAME.
No code signing or checks prevent running your relinked build. No warranty.
